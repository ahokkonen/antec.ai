# Лицензии и сценарии распространения

Обновлено: 2026-11-21. Это инженерная оценка, не юридическое заключение. Перед продажей платформы
клиентам нужна проверка юристом.

## Почему важен сценарий распространения

Copyleft-лицензии включают обязательства не при любом использовании, а при определённых действиях:

| Лицензия | Когда включаются обязательства | Что придётся сделать |
| --- | --- | --- |
| MIT, Apache-2.0, BSD, PostgreSQL | Почти никогда | Сохранить уведомления об авторстве и текст лицензии |
| MPL-2.0 (OpenBao) | При распространении изменённых файлов | Открыть изменения в этих файлах, остальной код не затрагивается |
| GPL | При передаче копий (распространении) | Предоставить исходники распространяемой программы и её производных |
| **AGPL-3.0** (Grafana, Zitadel, Garage) | При распространении **и** при изменении программы, если с ней по сети работают внешние пользователи | Предоставить исходники изменённой версии этим пользователям. Без изменений достаточно дать ссылку на исходники и текст лицензии |
| **SSPL** (MongoDB) | Если функциональность программы предлагается третьим лицам как сервис | Открыть исходники всего стека, обслуживающего сервис (управление, UI, API, мониторинг, бэкапы). Для коммерческого хостинга практически неприемлемо |
| **Open WebUI License** | Инсталляция с более чем 50 пользователями за 30 дней; распространение и перепродажа | Сохранять брендинг. Для белой маркировки, массового распространения или перепродажи как SaaS нужна enterprise-лицензия |

## Три сценария

1. **Только внутри Mtech.** Ничего не распространяется. AGPL и SSPL фактически ничего не требуют.
   Open WebUI: сохранять брендинг.
2. **Mtech хостит платформу для клиентов (managed service).** Клиенты пользуются по сети.
   AGPL: если мы модифицируем AGPL-компонент, клиентам нужно дать исходники изменений.
   SSPL: под ударом весь наш стек, поэтому SSPL исключён. Open WebUI: вероятно, нужна
   enterprise-лицензия (перепродажа как сервис), проверить юридически.
3. **Передаём клиентам для установки у них.** Это распространение. AGPL/GPL: вместе с образами
   передаём исходники или ссылку на них и тексты лицензий; если наш код встроен в AGPL-программу
   (а не работает рядом как отдельный сервис), наш код тоже должен стать AGPL. Open WebUI: брендинг,
   возможно enterprise-лицензия при массовом распространении.

Практическое правило проекта: AGPL допускается только как **отдельный немодифицированный сервис**
(например, Grafana в своём контейнере), SSPL и BSL не допускаются, наш код не импортирует
copyleft-библиотеки.

## Выбранный сценарий (21.11.2026)

Сейчас сценарий 1 (только Mtech), затем сценарий 2 (Mtech хостит отдельные инсталляции клиентов).
Передача клиентам для установки у них (сценарий 3) не планируется.

Что это значит:

- **SSPL и BSL** исключены полностью.
- **AGPL** допустим только как отдельный немодифицированный сервис (например, Grafana).
  Если когда-нибудь модифицируем AGPL-компонент, клиенты, работающие с ним по сети, вправе
  получить исходники изменений.
- **Open WebUI** у клиентов: брендинг «Open WebUI» остаётся. Хостинг платформы для клиентов
  за деньги может считаться перепродажей как сервис, для которой лицензия требует enterprise-
  соглашения. До первого клиента с Open WebUI нужна юридическая проверка или запрос к Open WebUI.
  Клиенты с другим каналом (например, Teams) этого вопроса не касаются (ADR-0005).

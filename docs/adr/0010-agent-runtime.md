# ADR-0010: Агентный рантайм: Pydantic AI за адаптером, подтверждения без DBOS

- Статус: предложено
- Дата: 2026-11-22
- Ответственный: CTO
- Связанные: ADR-0001, ADR-0003, ADR-0004, ADR-0006, ADR-0007, ADR-0008, ADR-0009,
  ADR-0012 (в очереди), [architecture/overview.md](../architecture/overview.md)

## Контекст

Platform API отдаёт модели через OpenAI-совместимый фасад (ADR-0006), права решает Cerbos
(ADR-0009), инсталляция описывает модели, MCP-серверы и настройки манифестом (ADR-0008), раздел
`agents` зарезервирован под этот ADR. В overview.md рантайм запланирован как «Pydantic AI + DBOS».
Сценарии v1: чат-агент с инструментами M365 и Git, необратимые действия только после
подтверждения человеком, каждый вызов модели и инструмента в аудите, агент не получает больше
прав, чем пользователь (AGENTS.md, правило 5). Coding-агенты подключаются снаружи (OpenCode через
LiteLLM) и рантайм не используют.

Факты (проверено 2026-11-22, карантин 7 дней: релизы до 2026-11-15):

- Pydantic AI (`pydantic-ai-slim`, MIT): 2.68.0 от 2026-11-12, последняя 2.71.0 (релизы почти
  каждый день). Отложенные инструменты: инструмент с `requires_approval=True` завершает запуск
  результатом `DeferredToolRequests`; запуск продолжается вызовом с `message_history` и
  `deferred_tool_results` (`True` или `ToolDenied`). Модель OpenAI принимает `openai_user`.
  Модуль модели OpenAI не импортирует `tiktoken`, extra `[openai]` не нужен. Без
  `PYDANTIC_AI_NO_BANNER=1` при первом запуске агента печатается рекламный баннер.
- Набор `pydantic-ai-slim==2.68.0` + `openai==3.51.0` (Apache-2.0): 21 пакет, все лицензии из
  разрешённого списка, OSV пусто. Новые: `httpx2` (BSD-3-Clause, pydantic/httpx2, HTTP-клиент
  `openai` 3.x) рядом с нашим `httpx` 0.28, `genai-prices` (MIT; обновление цен из сети только
  явным `UpdatePrices`), `griffelib` (ISC), `jiter`, `logfire-api`, `pydantic-graph`, `truststore`.
- С extras `[mcp]` и DBOS 3.5.0 набор вырастает до 71 пакета: `psycopg` и `psycopg-binary`
  (LGPL-3.0, обязательная зависимость DBOS; ADR-0006 psycopg исключил), `email-validator`
  (Unlicense), `regex` (CNRI-Python), `cffi` (MIT-0), fastmcp-slim со своим стеком.
- Deep Agents 0.7.38 (LangChain 1.5.0, LangGraph 1.2.22): 82 пакета; обязательны SDK
  `anthropic`, `google-genai`, `google-auth` и клиент `langsmith`; состояние в PostgreSQL через
  `langgraph-checkpoint-postgres` = psycopg (LGPL-3.0); `langchain-mcp-adapters` 0.3.2 требует
  `mcp<2.0`; в комплекте файловая система и shell, модель безопасности проекта «trust the LLM».
- MCP 2026-07-28 без сессий и handshake: клиенту достаточно `tools/list` и `tools/call` по POST.
  `mcp-types` 2.3.0 (MIT, только pydantic): официальные типы сообщений. Поддержку 2026-07-28 в
  SDK `mcp` 2.3.0 по исходникам подтвердить не удалось.

## Решение

1. **Рантайм: Pydantic AI 2.68.0 за интерфейсом `AgentRuntime`** (`antec_platform/agents.py`).
   Зависимости `pydantic-ai-slim` и `openai`, без extras. Правила заменяемости:
   - `pydantic_ai`, `openai` и `httpx2` импортируются только в `antec_platform/adapters/`
     (тест границ импорта в CI);
   - типы Pydantic AI не выходят из адаптера: в БД, аудит и API идут только наши структуры;
     внутреннее состояние фреймворка (история для продолжения после подтверждения) хранится одним
     полем JSONB и может быть отброшено при смене рантайма;
   - тесты рантайма проверяют контракт `AgentRuntime`;
   - не используются граф (`pydantic-graph`), capabilities, встроенные инструменты провайдеров и
     Logfire; баннер выключен (`PYDANTIC_AI_NO_BANNER=1`).
2. **Durable execution в v1 без DBOS.** Запуск агента идёт в процессе Platform API в пределах
   запроса с лимитами шагов, вызовов инструментов и времени. Ожидание подтверждения хранится в
   `agent_runs` (статус, история фреймворка, ожидающие вызовы, срок). `WorkflowEngine` и DBOS
   откладываются до долгих фоновых процессов (отдельный ADR с решением по psycopg).
3. **Агент в манифесте** (раздел `agents`, схема манифеста v2; v1 остаётся валидной):
   `name` (`agent-<имя>`), `description`, `model` (логическая модель манифеста), `instructions`
   или `instructions_file` (файл в репозитории инсталляции), `tools` (`<mcp_server>.<tool>` из
   `mcp_servers`), `max_steps` (1-50, по умолчанию 10), `max_tool_calls` (0-100, по умолчанию 20).
   Имена агентов начинаются с `agent-`, имена моделей нет: одно пространство имён без
   таблицы соответствий. Рендер пишет `agents.json` (с текстом инструкций) для Platform API.
4. **Фасад.** Агенты видны в `GET /v1/models` и вызываются `POST /v1/chat/completions` (поток SSE
   и без). Вызов агента требует `invoke` на ресурс `agent` и `invoke` на его модель (агент не
   получает модель, недоступную пользователю); список показывает агента, только если разрешено
   и то и другое. Инструкции агента задаёт манифест: системные сообщения клиента и параметры
   генерации не передаются; из истории берутся текстовые сообщения пользователя и ассистента,
   последнее сообщение должно быть от пользователя. Базовая политика ядра (`policies/cerbos`):
   `platform-user` вызывает любого агента, `platform-admin` всё; сужает инсталляция.
5. **Вызовы модели агентом** идут в LiteLLM ключом `platform-api` с `user` = id пользователя
   Platform API (бюджет конечного пользователя, ADR-0006, п. 7), без повторов в SDK. Каждый шаг
   записывается в `model_calls` со ссылкой `agent_run_id` и событием аудита `model.call`; запуск
   целиком в `agent_runs` и событием `agent.run`. История разговора: новые сообщения
   пользователя и итоговый ответ агента.
6. **Инструменты** (второй шаг реализации): свой MCP-клиент в `adapters/` (ревизия 2026-07-28,
   httpx, типы `mcp-types`); перед каждым вызовом Cerbos (`tool`, id `<server>.<tool>`, действие
   `call`, субъект = пользователь), затем обмен токена пользователя на токен с аудиторией сервера
   (ADR-0007); всё, что не помечено `read_only` в манифесте, только после подтверждения; аудит
   `tool.call` (allow, deny, error, кто подтвердил). Базовая политика: `platform-user` вызывает
   инструменты из манифеста.
7. **Подтверждение** (второй шаг): агент отвечает «Нужно подтверждение: <инструмент, аргументы>.
   Ответьте „подтверждаю <код>“ или „отмена“». Решает код Platform API по точному совпадению
   последнего сообщения пользователя в том же разговоре (`X-OpenWebUI-Chat-Id`), срок 15 минут.
   Адаптеры каналов (Teams, Telegram) получают `POST /v1/agent-runs/{id}/decision` с токеном
   пользователя для своих кнопок.
8. **Порядок реализации**: PR A (этот ADR, агенты в манифесте и фасаде, `agent_runs`, аудит,
   политика `agent`; агенты без инструментов), PR B (MCP-клиент, token exchange, политика `tool`,
   подтверждения, тестовый MCP-сервер `mcp-demo` и клиент Keycloak в dev-инсталляции).

## Последствия

- Плюс: агенты доступны любому клиенту фасада без изменений клиента; права, бюджеты и аудит те же,
  что у моделей.
- Плюс: без новых сервисов и лицензий вне разрешённого списка.
- Плюс: переход на LangGraph или другой рантайм: новый адаптер `AgentRuntime` и обёртка
  инструментов, оценка 1-2 недели; ожидающие подтверждения при переходе истекают.
- Минус: частые релизы Pydantic AI; обновление только после карантина и тестов контракта.
- Минус: в образе два HTTP-клиента (`httpx` и `httpx2`).
- Минус: сбой процесса посреди запуска теряет запуск; запись `agent_runs` остаётся в статусе
  `started` до задачи очистки (ADR-0012).
- Минус: стоимость шагов агента пустая до колбэка расходов LiteLLM (как у потоковых вызовов).
- Сделать: overview.md: рантайм «Pydantic AI», durable execution своё; PR B.

## План выхода (как заменить)

Граница `AgentRuntime` и описание агента в манифесте: другой рантайм (LangGraph, свой цикл)
подключается новым адаптером; фасад, политики, аудит, история, MCP-клиент и подтверждения
остаются. Долгие процессы: `WorkflowEngine` (DBOS, Temporal) отдельным ADR.

## Допущения и открытые вопросы

- Допущение: запуск агента в пределах HTTP-запроса укладывается в таймаут шлюза (300 с); долгие
  задачи не входят в v1.
- Допущение: текстового ответа хватает для v1; изображения во входе агента не передаются.
- [ ] Задача очистки зависших `agent_runs` и срок хранения истории фреймворка (ADR-0012).
- [ ] Стоимость шагов агента: колбэк расходов LiteLLM (ADR-0001, п. 4).
- [ ] Поддержка MCP 2025-11-25 для внешних серверов.
- [ ] Ответ MCP `input_required` (MRTR, elicitation) не поддерживается: такой вызов = ошибка
      инструмента.
- [ ] Аудит `tool.call` пишется после вызова; при сбое записи аудита вызов уже выполнен
      (сбой логируется). Запись до вызова: вместе с ADR-0012.

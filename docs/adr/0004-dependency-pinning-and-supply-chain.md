# ADR-0004: Закрепление версий и защита цепочки поставок

- Статус: принято
- Дата: 2026-11-21
- Ответственный: CTO
- Связанные: ADR-0001, ADR-0002, [policy/allowed-versions.yaml](../../policy/allowed-versions.yaml)

## Контекст

В 2026 году кандидаты в стек и инструменты безопасности уже пострадали от атак на цепочку поставок:
LiteLLM дважды (март: 1.82.7 и 1.82.8; октябрь: 1.107.0 вместе с плавающими Docker-тегами),
причём мартовская атака прошла через заражённый GitHub Action сканера Trivy. Вредоносный
1.107.0 был подписан действующим тогда ключом. Вывод: подпись и известное имя проекта не
гарантируют чистоту артефакта. NIS2 требует управлять рисками цепочки поставок.

## Решение

1. **Реестр версий** `policy/allowed-versions.yaml` единственный источник истины: разрешённые
   версии, минимальные версии, кандидаты, denylist (версии, теги, дайджесты), источники.
2. **Образы только по digest**: `image:tag@sha256:...`. Плавающие теги запрещены всегда.
   Пре-релизы (rc, beta, dev) запрещены в продакшне.
3. **Python-зависимости** только через `uv lock` с хэшами и `uv sync --locked`. Пакеты из
   denylist блокируются в CI.
4. **GitHub Actions и другие CI-действия** закрепляются по полному SHA коммита.
5. **Карантин 7 дней** для не-security релизов. Security-релизы ставятся быстрее, но после
   сверки с advisories и denylist.
6. **Проверка перед добавлением версии в реестр**: release notes, GHSA/OSV по компоненту,
   подпись (cosign) там, где проект подписывает, сравнение digest с denylist, дата публикации
   артефакта не совпадает с окном известного инцидента.
7. **Собственное зеркало реестра образов.** Сервера тянут образы только из зеркала; в зеркало
   попадают только дайджесты из реестра.
8. **SBOM и сканирование** каждого собранного образа; SBOM хранится рядом с релизом.
9. **Мониторинг**: еженедельная проверка advisories по всем компонентам реестра; подписка на
   security-рассылки ключевых проектов.
10. **Если разрешённая версия оказалась скомпрометированной**: перевести в denylist, остановить
    сервис, ротировать все секреты, к которым он имел доступ (начиная с ключей провайдеров,
    master key и пароля БД), пересобрать хост, развернуть чистую версию, оценить необходимость
    уведомления по NIS2 (раннее предупреждение 24 ч, уведомление 72 ч).

## Последствия

- Плюс: обновление нельзя поставить «случайно»; каждое изменение версии видно в PR.
- Минус: обновления медленнее (карантин, ревью). Принято сознательно.
- Сделать: CI-проверка, которая сверяет docker-compose и `uv.lock` с реестром
  (digest обязателен, версия в allowed, нет совпадений с denylist).

## План выхода

Политика не зависит от инструментов: реестр в YAML, проверки реализуются любым CI.

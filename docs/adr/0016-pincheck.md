# ADR-0016: pincheck: CI-проверка реестра версий и уточнения ADR-0004

- Статус: предложено
- Дата: 2026-11-21
- Ответственный: CTO
- Связанные: ADR-0001, ADR-0004, ADR-0005, [policy/allowed-versions.yaml](../../policy/allowed-versions.yaml),
  [tools/pincheck](../../tools/pincheck/README.md)

## Контекст

ADR-0004 требует CI-проверку, которая сверяет docker-compose и `uv.lock` с реестром версий.
При реализации нашлись места, которые ADR-0004 и реестр не определяли однозначно:

- пре-релизы запрещены «в продакшне», но CI не знает, куда пойдёт артефакт;
- `digest: null` в реестре означает «в prod нельзя», но образы в ядре ещё не зафиксированы;
- у компонентов были разные форматы версий (`1.108.7` + `image_tag: v1.108.7` у LiteLLM,
  `v0.13.3` у Open WebUI), а в поле `image` встречался свободный текст;
- не было сказано, как закреплять сам uv и GitHub Actions и относятся ли они к реестру;
- правило «пакет litellm не импортируем» было записано только текстом.

## Варианты

| Вариант | Версия, лицензия | Плюсы | Минусы | Стоимость поддержки |
| --- | --- | --- | --- | --- |
| **Свой инструмент на Python (pincheck)** | наш код | Ровно наша схема реестра, понятные сообщения, тестируется на фикстурах, тот же стек, что у платформы | Код нужно поддерживать | Низкая: около 2300 строк вместе с тестами |
| Политики OPA/Conftest по YAML | Apache-2.0 | Стандартный движок политик | Rego для команды новый; разбор Dockerfile, `uv.lock` и нормализацию имён образов всё равно писать самим | Средняя |
| Renovate/Dependabot + ручное ревью | AGPL-3.0 / проприетарный сервис | Автоматические PR обновлений | Не запрещают обход реестра, только предлагают обновления | Не решает задачу |

Размещение pincheck:

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| **Отдельный uv-проект `tools/pincheck/`** | Зависимости CI-проверки изолированы от платформы; инструмент без изменений используется в репозиториях инсталляций (ADR-0005); свой `uv.lock` сразу проверяется самим pincheck | Отдельный lock-файл |
| Пакет в uv workspace в корне | Один lock на весь репозиторий | Обновление зависимостей платформы затрагивает CI-проверку и наоборот; workspace в корне сейчас создаётся только ради одного пакета |

## Решение

1. **pincheck** в `tools/pincheck/` как отдельный uv-проект: Python 3.12+, Pydantic, PyYAML,
   argparse. CLI: `pincheck --policy policy/allowed-versions.yaml [пути...]`. Код выхода 0 или 1
   (2 только при неверных аргументах CLI). Workflow `.github/workflows/pincheck.yml` запускается
   на каждый PR и push в main.
2. **Уточнения ADR-0004:**
   - Пре-релизы (rc, beta, alpha, dev и т.п.) запрещены **всегда**, не только в prod.
     Поле реестра `prerelease_forbidden: true` (вместо `prerelease_forbidden_in_prod`).
   - Образ в compose или Dockerfile без `@sha256:` даёт ошибку **всегда**, независимо от флагов.
   - `digest: null` в реестре для используемого компонента даёт предупреждение. Флаг
     `--require-digest` делает его ошибкой: так запускают prod и репозитории инсталляций.
   - `digest` в реестре относится к первой версии из `allowed` (текущей). Для остальных версий
     из allowed выдаётся предупреждение (ошибка с `--require-digest`).
   - digest из любого `denied.image_digests` запрещён для **любого** образа, а не только для
     образа своего компонента: так ловятся варианты (`litellm-database`) и зеркала. То же для
     `digest` в реестре: он не должен совпадать с denylist никакого компонента.
   - Усечённые digest из публикаций об инцидентах кладутся в `denied.image_digest_prefixes` и
     сверяются по префиксу. Минимальная длина префикса 12 hex-символов; короче, с многоточием
     или полный digest считаются ошибкой схемы реестра. Префикс заменяется полным digest, как
     только полное значение подтверждено вторым источником.
   - Каждая запись `image_digests` и `image_digest_prefixes` содержит `source` (https-ссылка) и
     `confidence`: `multi-source` (обязателен `corroborated_by`) или `single-source`.
     Single-source записи тоже блокируют: ложная блокировка дешевле пропущенного вредоносного образа.
3. **Формат реестра:**
   - `allowed`, `min_version`, `candidate.version` содержат только числа через точку, без префикса.
     Префикс тега задаётся полем `image_tag_prefix` (например, `"v"`).
   - `image` содержит только репозиторий без тега и digest, либо `null` с пояснением в `note`.
   - `python_forbidden` перечисляет пакеты, запрещённые в любой версии (сейчас `litellm`, ADR-0001).
     `python_min_versions` задаёт минимальные версии Python-пакетов.
   - Неизвестные поля запрещены, чтобы опечатка не отключала правило молча.
4. **GitHub Actions и uv не входят в реестр.** Actions закрепляются по полному SHA коммита с
   версией в комментарии; SHA проверяется через GitHub API по тегу релиза. Версия uv и
   sha256 архива задаются в workflow. Карантин 7 дней действует и для них: берётся последний
   релиз старше 7 дней.
5. **Разрешённые лицензии** (заменяет список в AGENTS.md и brief.md): MIT, Apache-2.0,
   BSD-2-Clause, BSD-3-Clause, ISC, PSF-2.0, PostgreSQL. MPL-2.0 допустима без модификаций.
   Всё остальное требует согласования. PSF-2.0 добавлена, потому что под ней `typing-extensions`,
   обязательная зависимость pydantic; ISC распространена в экосистеме и по смыслу равна MIT.
6. **Карантин для Python-зависимостей инструментов:** `exclude-newer` в `pyproject.toml`
   ограничивает и транзитивные пакеты датой не позже чем 7 дней до последнего обновления lock.

## Последствия

- Плюс: обход реестра (образ без digest, плавающий тег, вредоносный digest, litellm в `uv.lock`)
  ломает PR.
- Плюс: тот же инструмент используется в репозиториях инсталляций с `--require-digest`.
- Минус: свой код проверки нужно поддерживать и покрывать тестами.
- Минус: тестовые фикстуры содержат нарушения намеренно, поэтому при проверке репозитория
  они исключаются (`--exclude tools/pincheck/tests/fixtures`).
- Минус: сверка по префиксу может дать ложное срабатывание на чистом образе; вероятность
  совпадения 12 hex-символов около 1 к 2.8·10^14, это принято.
- Сделать: зафиксировать `image` у postgresql (собственная сборка) и openbao, когда появятся
  образы; заполнить `digest` по ADR-0004 перед первым развёртыванием.

## План выхода (как заменить)

Реестр остаётся YAML-файлом с описанной схемой; pincheck лишь его читает. Замена на OPA/Conftest
или другой инструмент требует переписать проверки, реестр и workflow не меняются. Оценка: 1 неделя.

## Допущения и открытые вопросы

- Допущение: compose-файлы и Dockerfile указывают образы литералами; переменные в имени образа
  запрещены, потому что их нельзя проверить статически.
- [x] Лицензия PSF-2.0 (`typing-extensions`): добавлена в разрешённые, решение 5.
- [ ] Полные index-digest вредоносных `litellm-database` и `litellm-non_root` v1.107.0
      опубликованы только усечёнными. Сейчас они в `image_digest_prefixes`, платформенные
      манифесты в `image_digests` с `confidence: single-source` (TODO в реестре).
- [ ] Автоматическая проверка лицензий зависимостей в CI: отдельная задача в бэклоге.

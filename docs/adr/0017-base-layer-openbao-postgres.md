# ADR-0017: Базовый слой: OpenBao, PostgreSQL, бутстрап секретов и локальный стенд

- Статус: предложено
- Дата: 2026-11-21
- Ответственный: CTO
- Связанные: ADR-0003, ADR-0004, ADR-0005, ADR-0016, [deploy/compose](../../deploy/compose/README.md)

## Контекст

Все сервисы платформы (Keycloak, LiteLLM, Open WebUI, Platform API, DBOS) зависят от PostgreSQL
(ADR-0003) и от хранилища секретов: секреты только в хранилище, никогда в коде, конфигах и `.env`
(AGENTS.md, правило 5). Нужен первый воспроизводимый слой, на котором строится остальное.

Ограничения на 2026-11-21:
- стенд пока локальный: Docker Desktop на Mac (arm64), виртуальная машина 8 CPU и 7,7 GB RAM;
- шаблона инсталляции ещё нет (ADR-0008), поэтому compose пока лежит в ядре (`deploy/compose/`);
- официальные образы пересобираются под тем же тегом: `postgres:18.7` пересобран 2026-11-20
  (обновление пакета PGDG), `keycloak:26.8.2` пересобран 2026-11-19. Digest тега меняется, а
  карантин ADR-0004 (7 дней) формально запрещает свежий digest.

## Варианты

| Вопрос | Вариант | Плюсы | Минусы |
| --- | --- | --- | --- |
| Хранилище OpenBao | **Встроенный Raft** | Нет зависимости от PostgreSQL; снапшоты встроены | Отдельный бэкап |
| | PostgreSQL | Один бэкап | Циклическая зависимость: пароль БД лежит в OpenBao |
| Доставка секретов в контейнеры | **Одноразовый secrets-render из OpenBao в том, файлы `*_FILE`** | Секретов нет на диске хоста, в `.env`, в окружении и argv | Перезапуск postgres без up.sh не обновит секреты |
| | `.env` / переменные окружения | Просто | Нарушает правило 5; видно в `docker inspect` |
| | OpenBao Agent (sidecar) | Ротация и продление | Сложнее; для статических паролей БД пока не нужно |
| Unseal локально | **1 доля ключа в Связке ключей macOS** | Похоже на прод (настоящий init, Raft, политики) | Только macOS |
| | dev-режим | Ноль настройки | Данные в памяти, root-токен известен, не похож на прод |
| pgvector | **Пакет PGDG с точной версией** | Подпись apt PGDG, одна строка | Старые версии могут уйти из репозитория |
| | Сборка из исходников | Полный контроль | Компилятор и dev-пакеты в сборке, дольше |
| Бэкап | **Логический: pg_dump + Raft-снапшот + проверка восстановления** | Просто, проверяемо | Нет PITR |
| | pgBackRest / WAL-G | PITR, инкременты | Новый компонент, отдельное решение |

## Решение

1. **OpenBao 2.7.2** в настоящем режиме с Raft-хранилищем. KV v2 смонтирован на `antec/`.
   Порт на хост не публикуется, доступ через внутреннюю сеть и `docker compose exec`.
   На локальном стенде TLS выключен; на сервере TLS обязателен (отдельная задача).
2. **Unseal на локальном стенде:** одна доля ключа и root token хранятся в Связке ключей macOS
   (`antec-local`) по идентификатору установки; идентификатор пишется в манифест каждого бэкапа.
   Удаление стенда (`--purge`) не удаляет ключи: без них снапшоты OpenBao старых бэкапов не
   восстановить. Ключи удаляются только явным `--forget-keys`. Скрипты передают ключи только
   через stdin и окружение docker CLI, не через argv.
   На сервере: 5 долей с порогом 3 или auto-unseal; решается до первой серверной инсталляции.
3. **Секреты PostgreSQL** генерируются при бутстрапе прямо в OpenBao (`antec/postgres`).
   Одноразовый `secrets-render` (тот же образ OpenBao, `read_only`, `cap_drop: ALL`) получает
   через stdin токен на 5 минут с правом только читать `antec/data/postgres` и пишет файлы `0400`
   в отдельный том. PostgreSQL читает их через `POSTGRES_PASSWORD_FILE` и init-скрипт.
4. **PostgreSQL 18.7** собирается локально как `localhost/antec/postgres:18.7-pgvector0.8.7` от
   `postgres:18.7@sha256:…` с пакетом `postgresql-18-pgvector=0.8.7-1.pgdg13+2`. На каждый сервис
   отдельная БД, роль и лимит соединений; `PUBLIC` лишён прав; `vector` только в `platform`.
5. **Сети:** `secrets` и `data` с `internal: true`, без выхода наружу и без публикации портов.
   Все сервисы: `cap_drop: ALL` (возвращаются только права, нужные entrypoint), `no-new-privileges`,
   лимиты памяти, healthcheck.
6. **Бэкап и проверка восстановления:** `backup.sh` (pg_dump каждой БД, роли без паролей,
   Raft-снапшот, манифест с sha256, числом строк и канарейкой) и `restore-verify.sh`
   (восстановление в одноразовые контейнеры с `--network none`, сверка с манифестом, распечатывание
   снапшота OpenBao ключом установки из манифеста, назначение ролям паролей из восстановленного
   OpenBao и вход каждой роли в свою БД по SCRAM). Это первый шаг к критерию выхода MVP
   «восстановление проверено».
7. **Пересборка разрешённой версии под тем же тегом** допускается без 7-дневного карантина, как
   security-релиз по п. 5 ADR-0004, если выполнено всё:
   - версия компонента уже в `allowed`, меняется только digest;
   - подпись проверена, а при её отсутствии BuildKit provenance совпадает с официальным
     источником сборки (для Docker Official Images: коммит в `docker-library/official-images`);
   - digest не в denylist;
   - в реестре записано, что и когда проверено.
8. **Локальные сборки** (`build:`) допускаются в compose только как `localhost/antec/<имя>:<версия>`
   с `pull_policy: build`, без плавающих тегов и пре-релизов; Dockerfile сборки (включая
   `build.dockerfile` и `dockerfile_inline`) проверяется pincheck всегда, удалённые контексты и
   `additional_contexts` запрещены (PIN022).
9. **CI:** pincheck с `--require-digest` по `deploy/compose`, проверка `docker compose config`,
   синтаксиса каждого скрипта и сборки образа postgres.

## Последствия

- Плюс: секреты не лежат ни в репозитории, ни на диске хоста, ни в окружении контейнеров.
- Плюс: восстановление PostgreSQL и OpenBao проверяется одной командой.
- Минус: стенд запускается только через `scripts/up.sh` (нужен unseal и выгрузка секретов).
- Минус: локальный unseal завязан на macOS; на Linux-сервере нужен другой механизм.
- Минус: логический бэкап не даёт восстановления на момент времени (PITR).
- Минус: полный состав MVP (около 17 GB RAM) не помещается в текущую VM Docker (7,7 GB).

## План выхода (как заменить)

Контракты стандартные: протокол PostgreSQL и Vault API. Замена OpenBao на Vault или Infisical
меняет `render.sh` и `up.sh`; сервисы читают секреты из файлов и не знают об источнике.
Замена логического бэкапа на pgBackRest не меняет compose-сервисы.

## Допущения и открытые вопросы

- Допущение: на локальном стенде нет конкурентной записи во время бэкапа, поэтому число строк
  в манифесте снимается отдельным запросом перед `pg_dump`.
- [ ] Unseal и TLS OpenBao на сервере (доли ключа или auto-unseal, сертификаты).
- [ ] Непрерывный WAL-архив и PITR: pgBackRest или WAL-G, отдельный ADR.
- [ ] OpenBao Agent для ротации паролей сервисов, когда появятся динамические секреты.
- [ ] Ресурсы для полного MVP: увеличить память VM Docker или перейти на сервер.

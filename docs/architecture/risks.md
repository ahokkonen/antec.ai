# Риски

Обновлено: 2026-11-21.

| Категория | Риск | Мера |
| --- | --- | --- |
| Безопасность | Компрометация зависимости или образа (у LiteLLM два случая в 2026) | ADR-0004: реестр версий, digest, карантин, зеркало, SBOM; лимиты расходов у провайдеров; ротация ключей |
| Безопасность | LiteLLM хранит ключи всех провайдеров: взлом шлюза = утечка всех ключей | Отдельная сеть, исходящий трафик только к провайдерам, ключи в OpenBao, лимиты и алерты у провайдеров, MCP-шлюз LiteLLM не используем |
| Безопасность | Уязвимости контроля доступа в Open WebUI (серия CVE в 2026) | UI без канонических данных и без RAG; исполнение кода в UI отключено; патчи за 72 ч; права проверяет Platform API |
| Безопасность | Косвенная prompt injection через письма, календарь и файлы OneDrive | Минимальные scopes Graph; подтверждение человеком для отправки и записи; внешний контент помечается как данные; red-team в CI |
| Безопасность | Агент получает больше прав, чем пользователь | Делегированные токены пользователя; Cerbos на каждый вызов; контрактные тесты |
| Безопасность | Все данные разрешено отправлять в облако (v1) | DPA с провайдерами, режимы без хранения и обучения, PII-маскирование для журналов; пересмотр в v2 |
| Безопасность | NIS2: раннее предупреждение 24 ч, уведомление 72 ч, отчёт за месяц | Runbook инцидентов, алерты из аудита, учения раз в квартал |
| Безопасность | Один хост и один PostgreSQL в MVP | Бэкапы вне хоста, проверенное восстановление, документированный RTO |
| Безопасность | Инсталляции клиентов отстают по версии ядра и не получают патчи (ADR-0005) | Поддержка только N и N-1; security-патч ядра автоматически открывает PR во всех репозиториях инсталляций; отчёт о версиях всех инсталляций |
| Комплаенс | EU AI Act, ст. 50 (действует с 2 августа 2026): пользователь должен знать, что общается с ИИ; для чат-ботов под своим брендом возможны обязанности провайдера | Уведомление в каждом канале (веб, Teams, мессенджеры); юридическая оценка роли Mtech (провайдер или deployer) для клиентских инсталляций |
| Комплаенс | GDPR: обработка данных сотрудников и клиентов, отправка в облачные модели | DPIA до запуска, реестр обработки, DPA с провайдерами, сроки хранения |
| Лицензии | Open WebUI: брендинг при >50 пользователях; хостинг для клиентов может потребовать enterprise-лицензию | Юридическая проверка до первого клиента с Open WebUI (`security/licensing.md`); UI заменяем (ADR-0002) |
| Лицензии | Open-core: нужные функции платные (LiteLLM SSO/JWT/аудит) | Архитектура не опирается на платные функции (ADR-0001) |
| Лицензии | AGPL в поставке клиентам | Только отдельные немодифицированные сервисы |
| Vendor lock-in | Привязка к UI или шлюзу | Канонические данные в Platform API, OpenAI-совместимые границы, адаптер `GatewayAdmin` |
| Vendor lock-in | Привязка к M365 и Entra ID | Только через OIDC-федерацию и MCP-адаптеры; ядро работает без них |
| Стоимость | Токены, особенно coding-агенты | Бюджеты на пользователя и команду с первого дня, отдельные лимиты для coding-агентов |
| Стоимость | Эксплуатация силами начинающих DevOps | Одна СУБД (ADR-0003), минимум stateful-сервисов, runbook на каждый |
